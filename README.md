# Azeroth Commerce Authority — торговые маршруты

Мне надоели вечные неудобные аддоны внутри игры, поэтому эту рутину я решил упростить через простой навайбкоженный сайт.

Планировщик для WoW Forever, EU PvP, Альянс: 150 заказов, четыре маршрута, карты, расчёт репутации и калькулятор Merchant’s Favor для рецептов. Это статический сайт без сервера приложений и внешних библиотек.

## Запуск

Откройте опубликованный сайт либо скачайте `Azeroth-Commerce-Authority-Windows.zip`, распакуйте архив и откройте `index.html` в Microsoft Edge или другом современном браузере. Для архива не нужны Python, Node.js или локальный сервер. Карты, каталог и маршруты встроены в HTML и доступны без интернета.

Исходную версию на macOS можно запустить двойным щелчком по `start.command` или командой `./start.command`. Адрес — `http://localhost:8766`; сервер слушает только локальный интерфейс. Для остановки нажмите Ctrl+C в его терминале.

## Цены, персонажи и сохранения

Кнопка обновления цен запрашивает новый снимок рынка EU PvP Alliance через интернет. Проверяйте дату снимка в интерфейсе. При ошибке остаётся предыдущий снимок; без сети можно продолжать пользоваться сохранёнными данными. Цены выставленных лотов не гарантируют наличие нужного количества или стека. Расходы на перелёты и случайный возврат Coin Pouch не превращают эту оценку в обещание окупаемости.

Для каждого персонажа используйте отдельный профиль и задайте репутацию из игры. Отметки покупок и сдач сохраняются в браузере; следующий круг запускается вручную и сохраняет начисленную репутацию. При расхождении с игрой скорректируйте репутацию через форму сайта.

Профили и личный прогресс хранятся только в вашем браузере. Они не публикуются в GitHub Pages и не синхронизируются с согильдийцами. Хранилища `localhost`, `127.0.0.1`, опубликованного сайта и автономного файла разные. Для продолжения используйте тот же адрес или файл в той же папке и тот же браузер; избегайте приватного режима.

Перед заменой автономного HTML, очисткой браузера или переносом на другой компьютер экспортируйте резервную копию через интерфейс сайта. Затем импортируйте её на новом месте. Копия содержит ваши профили и отметки: храните её локально, не добавляйте в публичный репозиторий.

## Монеты и рецепты

Во вкладке **«Монеты и рецепты»** укажите текущий баланс Merchant’s Favor из игры. Выберите рецепты любых профессий либо желаемый баланс монет. План показывает сумму первоначальной закупки, подтверждённое серебро за сдачи и расход после возврата, а также точные названия и количества ящиков и материалов.

Калькулятор сравнивает все 30 видов ящиков и 96 вариантов заполнения. Он учитывает следующие ценовые уровни и ограниченное количество товаров в снимке. Закупка покрывает цель без случайных удвоений; Performance Bonus отображается только как прогноз. Серебро Artisan пока не подтверждено и не вычитается. Личный баланс обновляется вручную и сохраняется отдельно у каждого персонажа.

Каталог содержит рецепты всех семи профессий с ценой, навыком, репутацией и продавцом. Две спорные инженерные схемы помечены отдельно и недоступны для добавления в корзину. Репутацию можно планировать заранее: требование выше текущей репутации не мешает выбрать рецепт.

Цены — минимум опубликованной модели единиц товара. Источник агрегирует лоты и не сохраняет размеры отдельных стеков, поэтому реальный выкуп целых стеков может стоить дороже. Неизвестные цены не считаются нулевыми, а нехватка данных не заменяется бесконечным запасом дешёвых товаров. Сдавайте заполненные ящики Marcy Baker в Three Corners; нейтральный аукцион лагеря не входит в выбранный рынок Альянса.

## Сборка автономного файла

Из корня проекта:

```sh
python3 build_portable.py
```

Результат — `portable/index.html`, инструкция `portable/README.txt` и архив `Azeroth-Commerce-Authority-Windows.zip`. Сборка включает CSS, восемь JSON-файлов и скрипты `site-config.js`, `planner-core.js`, `prices.js`, `favor-core.js`, `favor-ui.js`, `app.js` в указанном порядке.

Для связи автономной и опубликованной версий:

```sh
python3 build_portable.py --site-url https://USERNAME.github.io/aca-route-planner/ --download-directory dist/downloads
```

Замените `USERNAME` своим именем на GitHub. Параметр `--site-url` принимает HTTPS-адрес и записывает его в `dist/site-config.js` и автономный HTML. Параметр `--download-directory` дополнительно копирует ZIP в указанный каталог; относительный путь считается от корня проекта. При публикации архив доступен по адресу `downloads/Azeroth-Commerce-Authority-Windows.zip` относительно сайта.

## Публикация в GitHub Pages

1. Создайте публичный репозиторий `aca-route-planner` с основной веткой `main`.
2. Поместите **содержимое папки `aca-local`** в корень нового репозитория: рядом должны находиться `dist`, `tests`, `build_portable.py` и `.github`. Саму внешнюю папку `aca-local` добавлять не нужно.
3. В настройках репозитория откройте **Settings → Pages → Build and deployment**, выберите **GitHub Actions**.
4. Отправьте изменения в `main` либо запустите workflow вручную во вкладке **Actions**.

Workflow запускает `node --test tests/*.test.cjs`, получает адрес из `actions/configure-pages`, собирает ZIP и публикует только `dist`. В опубликованный сайт входят исходные статические данные и архив для скачивания; персональные сохранения из браузера в сборку не попадают. Ссылку на результат показывает deployment `github-pages`.

После изменений JS, CSS, маршрутов или встроенного снимка цен нужно повторить сборку. Генерируемые `portable`, ZIP, `dist/downloads` и локальные снимки экрана исключены из Git; `dist` с исходниками остаётся в репозитории.
